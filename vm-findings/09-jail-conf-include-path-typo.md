# `recipes/jail.conf`'s `.include` path points at the wrong dataset

**Files:** `recipes/jail.conf`, `scripts/doctor.sh`
**Severity:** Bug — breaks the documented shared-jail.conf mechanism for
starting containers.

## The bug

`recipes/jail.conf` (the shipped default jail config, meant to be
installed as `/etc/jail.conf` or referenced with `-f`) ends with:

```
.include "/zshemot/parasa.git/recipes/containers/*/jail.conf";
```

`scripts/doctor.sh` has the identical string at line 310. But per
`stage0-bootstrap.sh`'s own `create_datasets()` and every other doc that
gets this right (`docs/idea.md`, `docs/user_stories_containers.md`,
`docs/bootstrapping/03_the_three_pools.md`), there is no
`zshemot/parasa.git` dataset at all:

- The parasa framework's **working checkout** is `zshemot/parasa`
  (mountpoint `/zshemot/parasa`, no `.git` suffix).
- `parasa.git` (the **bare git remote**) lives under a completely
  different pool: `zbamidbar/parasa.git`.

So `/zshemot/parasa.git/recipes/...` is wrong on two independent counts —
wrong suffix *and* wrong pool. The correct path, confirmed by
cross-referencing `docs/idea.md`
("The repo itself is cloned into `zshemot/parasa/`... configs via
`include "/zshemot/parasa/recipes/containers/*/jail.conf"`") and
`docs/user_stories_containers.md`, is:

```
.include "/zshemot/parasa/recipes/containers/*/jail.conf";
```

`docs/bootstrapping/06_recipes_system.md` and `docs/drift_manifest.md`
both repeat the same wrong `.git`-suffixed path, so the typo has spread
past just the one template file.

## Impact

Anyone following the documented workflow — bootstrap, clone parasa into
`zshemot/parasa`, install `recipes/jail.conf` as the system's jail
config, create containers, start them via `service jail start` — would
find that no per-container `jail.conf` ever actually gets included,
because the glob path doesn't resolve to anything. `jail(8)` would
silently see zero containers defined via the include (or error, depending
on jail.conf strictness), with no indication of why.

## How we hit it

Noticed inspecting `recipes/containers/demo1/jail.conf` (correctly
generated by `new_container.sh`, pointing at its own file directly) next
to the top-level `recipes/jail.conf` while working out how to start our
test container — the `.include` glob wouldn't have picked it up. Worked
around it for this test by invoking `jail(8)` with an explicit
`-f`/config path rather than relying on the include mechanism.

## Suggested fix

Change both occurrences of `/zshemot/parasa.git/recipes/` to
`/zshemot/parasa/recipes/` in `recipes/jail.conf` and `scripts/doctor.sh`,
and fix the same typo in `docs/bootstrapping/06_recipes_system.md` and
`docs/drift_manifest.md` for consistency with `docs/idea.md` and
`docs/user_stories_containers.md`, which already have it right.
