# The Recipes System

Recipes (configuration per target) live in `recipes/` within the parasa
repo clone on zshemot. The directory is organized by target type.

## Directory structure

```
recipes/
  jail.conf                    Default jail.conf, includes per-container configs
  foundations/
    ${NAME}/
      build.conf               SRC_BRANCH, KERNCONF, MAKE_JOBS (sysrc format)
  systems/
    ${NAME}/
      ${FOUNDATION}.foundation Contains artifact name; filename = foundation
      compose.sh               Opaque replay commands (pre_pkg/post_pkg)
      derivations.local        Custom text-to-binary entries
      mtree.dist               Baseline mtree for the target
      pkg.list                 Package list (auto-populated by save)
  containers/
    ${NAME}/
      (same as systems, plus:)
      jail.conf                Jail configuration for this container
      mount.fstab              All container mounts (processed by jail(8))
```

## The five recipe files

### 1. `${FOUNDATION}.foundation`

Links this target to a foundation. Filename = foundation name, contents =
artifact name (ZFS snapshot tag). See [Git Topology](05_git_topology.md).

### 2. `compose.sh`

Opaque replay commands. Structured as two functions:

```sh
pre_pkg() {
    # Before packages: create users, groups, base system prep
}

post_pkg() {
    # After packages: commands that depend on installed software
}
```

Called during creation and during update. Only contains commands that
can't be auto-detected (category 5 in stratified change tracking).

### 3. `derivations.local`

Per-target custom text-to-binary derivation entries. Same tab-separated
format as the global `etc/derivations/${VERSION}.db`:

```
source-file	derived-file	regeneration-command
```

Local entries override global ones. Checked first by `lookup_derivation()`
in `helpers.sh`.

### 4. `mtree.dist`

Filesystem manifest generated by `mtree -c -x -R time,nlink,flags -K sha512`.
Records content hashes (sha512) for all files in the target tree,
excluding `.git` (via `etc/mtree.ignore`). Used by `diff.sh` to detect
drift.

### 5. `pkg.list`

Full package list, auto-populated by `save.sh` via `pkg info -o`. Used
during update to reinstall packages on the new base.

## Container-only files

### `jail.conf`

Per-container jail configuration, included by `recipes/jail.conf` via
`.include "/zshemot/parasa/recipes/containers/*/jail.conf"`. Typical
contents:

```
mycontainer {
    host.hostname = "mycontainer";
    path = "/containers/mycontainer";
    mount.fstab = "/zshemot/parasa/recipes/containers/mycontainer/mount.fstab";
}
```

### `mount.fstab`

All container mounts. Processed by `jail(8)` at jail start (mounted) and
jail stop (unmounted). Contains data-lake mounts (zfs type) and any
cross-mounts (nullfs type). Shared datasets are marked with `# shared`
comments.

## Two-tier configuration

Build configuration uses a two-tier lookup via `msysrc()`:

1. **Target's `build.conf`** (in `recipes/foundations/${NAME}/`)
2. **`parasa.conf`** (repo root)
3. **Hardcoded default** (passed as third argument)

```sh
val=$(msysrc "$build_conf" SRC_BRANCH "stable/15")
```

Both files use `sysrc(8)` format.

## Global vs. local derivations

The global derivation database ships with parasa at
`etc/derivations/${VERSION}.db`. Version is resolved from the
foundation's `SRC_BRANCH`:

- `stable/15` -> `15.0`
- `releng/15.1` -> `15.1`
- `main` -> newest available db

Resolution is chained: find the newest db whose version <= target version.
Per-target overrides go in `derivations.local` in the target's recipes dir.
At runtime, `diff.sh` checks local first, then global.
